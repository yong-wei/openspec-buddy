# v0.31.0

## Auto Lite claim-first 选择语义

- 无 mapping 的 `status:ready` Issue 不再使选择器停机，而是以确定性派生的
  `issue-<编号>-<标题slug>` change_id 直接认领（claim 先于 propose 建立排他锁），
  claim 后由主模型完成 Explore、propose、回写唯一 mapping 标记，再重入入口实施。
  多代理并行时，竞态窗口被压缩到 claim 写入序列本身。
- 无目标选择时，单个 Issue 的认领前置检查不通过（外部/部分 Claim、mapping
  无效/重复/冲突、非 ready、开放 blockedBy、本地 change 缺失、tracking/series-parent
  标签）改为跳过并继续检查下一个，直到队列末端才停；候选集读取不完整
  （超过 50 上限、blockedBy 批量读取不完整）仍立即停止。
- `status:ready` 只允许挂在可独立执行的 Issue 上；父级/跟踪 Issue 必须使用
  `status:tracking`。

## Auto Lite 工作树守卫

- 新增 `scripts/lite/worktree-base.sh`：`enter` 在新认领前把当前工作树归位到
  `buddy.boundBranch` 并与 `buddy.boundBase`（缺省 `origin/$OPENSPEC_BUDDY_BASE_BRANCH`）
  快进对齐，工作树不干净或分叉时停止等待人工处置；`leave <change_id>` 在 Issue
  收尾后删除本地 claim 分支、切回绑定分支并对齐，删除前校验远端真源，
  存在未推送提交时拒绝删除。恢复自有活跃 Claim 时不执行 enter。
- 未配置 `buddy.boundBranch` 的仓库保持旧的 base 对齐行为。
