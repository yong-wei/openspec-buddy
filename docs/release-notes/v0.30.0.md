# v0.30.0

## Direct claim proposal adoption

- 没有 `change_id` 映射的开放 Issue 现在先建立可验证的 direct claim 和
  Development branch lock，再返回 OpenSpec Explore handoff。
- Explore 后，代理必须以同一 `change_id` 在原 Issue 上完成 Buddy proposal
  adoption，将 proposal artifacts 验证、提交并推送到配置的 base branch；不会
  创建重复 Issue。
- `apply --resume-active` 会在 base 因 proposal push 前进时，安全地刷新同一
  direct claim 的 base SHA 并快进未改动的 claim branch。租约、认领者和工作树
  身份不会变化；任何所有权、分支、映射、PR 或 base 历史异常都会停止。
- Auto Lite 继续只处理已有有效映射的 Issue，并明确将原始无映射 Issue 转至
  manual direct-claim 流程。
